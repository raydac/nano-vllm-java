## 1. Implementation Progress
- Sample `RussianCheckersHelloWorld`: terminal Russian draughts. User picks one colour; Qwen Jeff plays the other. User's pieces are drawn at the bottom (Black rotates the board 180°). Rank numbers and file letters are on both edges. A single legal move is shown in the prompt; Enter plays it. RAW choice among legal moves. Coordinate entry `a3 b4` / `A 3 B 4`. Jeff usage is documented on `playWithJeff`, `positionText`, `choose`, `narrow`, and `ask`.
- Qwen3.5 text chat (`qwen3_5`): Gated DeltaNet + gated full attention, leading partial RoPE, vision tensors skipped. Jeff-Qwen3.5-0.8B download script. `toJev()` uses the causal logits; no separate Jeff API.
- Compacted causal-graph construction and the generate tick without changing the public API.
- Shared packed-or-dense layer loading in `WeightLayers` (Qwen3, LFM2, BERT, Llama RoPE theta).
- Gemma 3 residual add and embed scale now go through `Ops` (vector kernels) instead of scalar loops.
- Head RMSNorm no longer flattens to rank-2; `RMSNorm.forward` already norms the last axis.
- `WeightBag.asDense` and `asDenseReleasingPacked` share one materialize path.
- Engine step binds KV/conv once via `bindStep`. Prefill slot mapping is its own method.
- `EspeakNgCompiledDict.latinMap()` is gone. `LATIN_MAP` is a `byte[]` of the same 288 entries (values 0–57).
- IQ4NL codebook lives once as `GgufIqTables.kvalues_iq4nl` (signed bytes). `GgufDequant` and `GgufIqDequant` no longer each keep an `int[]` copy.

## 2. Architecture & Technical Discoveries
- Qwen3.5 text is architecture `qwen3_5`, not an alias of `qwen3`. Full-attention layers use leading partial RoPE (text-only; MRoPE collapses when positions match). Linear layers keep conv + recurrent state in `DeltaNetStateArena`, cleared with the existing conv-state hook. HF names `model.language_model.*` and root `language_model.*` (Jeff checkpoint) both canonicalize to `model.*`. `q_proj` stays unfused (query | gate).
- `RMSNorm.forward` walks `numel / lastDim` rows, so a `[tokens, heads, headDim]` tensor matches the old reshape-to-2d-then-back path.
- `HfConfig` compact constructor freezes a null `ropeScaling` to an empty map, so `WeightLayers.ropeTheta` can call `containsKey` directly.
- `IntStream.toList()` is already unmodifiable; `List.copyOf` around it was an extra copy.
- Public `LLM.generate` / `generateTokenIds` overloads stay: they are the caller-facing surface.
- TornadoVM Maven coordinate is `8.0.0-jdk22plus` (JDK 22+, including 27). Optional `tornado-clblast` is compile-only. Multi-token dense GEMV uses CLBlast SGEMM when `libclblast` runs; one token stays on the Kernel API plan because CLBlast SGEMV returned NaN on POCL. A non-finite CLBlast result or a failed launch drops CLBlast for the rest of the process. `-Dnanollvm.tornado.clblast=false` keeps the kernel. The weight slice is copied once into a Tornado `FloatArray`. Chat attention stays a Loop Parallel kernel. cuDNN packed-QKV attention is CUDA-only and does not match causal grouped-query attention with a sliding window.
- OpenCL devices outside the sandbox: `0:0` Intel UHD Graphics 620 (Tornado default), `0:1` POCL CPU. A sandboxed `tornado --devices` sees only POCL. `etc/tornado.backend` is OpenCL only. The CUDA driver jar can still abort startup when `libcuda` is missing, so the TornadoVM bench child passes `-Dtornado.enabled.backends=OpenCL`. `libclblast.so.1` is on the SDK `lib` path.
- `KernelChatBench` child JVMs must use the context class loader URLs. Under `mvn exec:java`, `java.class.path` is Maven's classpath. The TornadoVM child must be started with the `tornado` command (`tornado.exe` on Windows): the Maven parent never loads the SDK, so a parent device probe skips TornadoVM even when `tornado --devices` lists both OpenCL devices. The extensionless `bin/tornado` in the Windows SDK is a shell script; CreateProcess error 193 is that file. The `windows` Maven profile sets `tornado.launcher` to `tornado.exe`. When `TORNADOVM_HOME` is set, profile `tornadovm-home` points `tornado.executable` at `$TORNADOVM_HOME/bin/<launcher>`. `KernelChatBench` already resolves PATH then `TORNADOVM_HOME/bin`.

## 3. Technical Debt & Refactoring
- GGUF IQ tables, Tornado kernels, and espeak dictionaries are data or numeric kernels. Do not “compact” them into shared abstractions.
- Causal graphs still repeat decoder-layer shape (attention + MLP + norms). A shared layer skeleton would hide architecture differences.
- `LLM` still has many one-line generate overloads. They exist so callers do not pass unused flags.

## 4. Current Work In Progress
- `KernelChatBench` on Windows resolves `tornado.exe` from `PATH` or `TORNADOVM_HOME/bin`, and the `windows` Maven profile sets `tornado.executable` to `tornado.exe`. Worker `--classpath` / `--params` are shell-quoted because TornadoVM pastes them into `os.system`/`cmd.exe`: unquoted `;` truncates the classpath (NoClassDefFoundError for library classes), and Unix single quotes break `Path.of`. The tornado child also drops `CLASSPATH` so the launcher cannot append it with a Unix `:`. Default model is `requireKernelChatBench()` (Qwen3-0.6B → Gemma3 → Jeff → Gemma4 → SmolLM2); compact ONNX prints a note that Tornado ratios are launch-bound.
- `JevLevel` javadoc now states RAW vs L0 (rotations, eight-state prior, ordered scores stay one prefill) and includes a two-engine usage example. `require` and `Builder.jevLevel` point at it.
- Russian checkers records (`Sq`, `Move`, `Played`, `Choice`, `Step`, `Hop`) have javadoc for the short components: file/rank axes, path vs captured vs crowned `result`, forced single-move turns, and a hop's land/victim.
- Board a–h axis is `Sq.column` (0 = a). `Step` uses `columnDelta` and `rankDelta`. Screen position in the rotated drawing is `across`, not `column`.
- Jeff's checkers prompt does not ask for a written plan. Jev reads the next letter and the chat template closes an empty think block. `positionText` lists pieces; `choiceLabel` notes captures, promotion, a win, or `landing taken at once`. The question states that preference order.
- Russian checkers sample is in (`RussianCheckersHelloWorld`). Rules covered by `RussianCheckersHelloWorldTest` (no model load). A live game still needs `models/Jeff-Qwen3.5-0.8B`.
- Qwen3.5 text load is in: hybrid Gated DeltaNet + gated attention, leading partial RoPE, delta-state arena, `models/download-jeff-qwen3.5-0.8b.sh`. Vision tower and the Jeff readout head are not loaded. `toJev()` uses the causal logits. Jeff safetensors use a `language_model.*` prefix; that now maps onto `model.*`. Real Jeff-Qwen3.5-0.8B loaded and produced one token.

## 5. Known Issues & Limitations
- Qwen3.5 support is text-only safetensors. Vision inputs, LoRA adapters, Qwen3-Next, and Qwen3.5 MoE stay rejected. GGUF is not a load path for `qwen3_5`.
- Tornado kernel tests skip when no Tornado device is on the module path. Maven Surefire does not launch the `tornado` CLI, so those tests skip there.
