## 2. Architecture & Technical Discoveries
- **Standing rule:** JDK-only runtime (Java 21+, optional Vector API). No third-party libs in library/sample JARs (test-scoped OK). TornadoVM is optional Maven deps (`tornado-api` provided, `tornado-runtime` runtime, both `optional`) — not transitive for consumers. No JNI/JNA/FFM/CLI for inference or G2P. ONNX/GGUF/safetensors/fastText parsed in Java.
- Load: `ContainerTransport` → `ArchitectureProcessor` (Causal / Embedding / Speech / Synthesis) bind → fill → create for transformer graphs. Whisper = HF safetensors only; Piper = ONNX initializers + sidecar JSON. fastText = dedicated `loadFastText` (no WeightBag fill).
- Share `LlmModel` / `PreparedRag`; one `LLM` is not concurrent-safe for generate (`cancel()` is). Close engines before model. `LlmModel` is `abstract sealed` → hidden `LlmModelImpl`. Peer graphs: `CausalLM` / `EmbeddingEncoder` / `SpeechToText` / `TextToSpeech` / `TextClassifier`. Non-chat engines skip KV (`numKvcacheBlocks` 0).
- Matmul: builder `cpuThreads` wins over `-Dnanollvm.cpu.threads`. Default = process-wide daemon pool; `.dedicatedMatmulPool()` owned and shut down on close; `.matmulExecutor` caller-owned; `.disableMultiCpu()` / 1 thread = sequential.
- `LLM` owns one `Random` (unseeded, or seed `1L` for synthesis; `Builder.random`). Injected into Sampler + Piper VITS. Generate lock is the only exclusive engine lock.
- ONNX: initializers only; FLOAT/FP16/BF16/DOUBLE load. BERT prefixes are structural. Conv vs ConvTranspose weight axes differ; spatial attrs on `ConvLayout`.
- Piper G2P: `dictsource` first, then compiled `phontab`+`{lang}_dict`, else letter-to-sound. Phoneme map uses IPA `ɡ` (id 66).
- Whisper: greedy multilingual; incremental decoder self-attn KV; Bluestein FFT log-mel. `LlmInSound.ofWav` / `ofPcm`; `Locale` null/ROOT = auto.
- Gemma 4 text QAT: flatten `text_config`; skip towers; packed int2/4/8 + SRQ; PLE after MLP; KV share.
- GGUF: packed default; late unpack when no other engine is live. Chat `qwen3` is unfused `blk.N.*`. Gemma/Llama GGUF rejected.
- Dense RAG: index embeds sequential unless caller `Executor`; each job uses `MatmulRuntime.sequential()`.
- SpotBugs `EI_EXPOSE_REP*` on tensors/KV/packed records is by design. Props = `nanollvm.*` / `NANOLLVM_*` only.
- JPMS exports: `models` / `llm` / `chat` / `rag` / `tokenizer` / `utils` / `exceptions`. Hidden: `engine` / `layers` / `tensor` / `internal` / `prompts` / `models.internal` / `models.llmcontainer` / `models.llmarch`. `ModuleExportsTest` locks this. Public `KernelBackend` in `utils` (**since 1.4.0**; `availableModes()` **since 1.4.1**). Kernels are process-wide (`FloatKernels` class init) — `KernelChatBench` forks one JVM per mode. Vector API is always a child with `--add-modules=jdk.incubator.vector`; do not gate it on the parent Tornado launcher’s incubator probe.

## 3. Technical Debt & Refactoring
- Attention O(n²); no float16 / TP / CUDA; most HF safetensors still FP32; fused packed dequant-dot still open
- RMSNorm / LayerNorm / Sampler still sequential over tokens or logit rows
- Optional GGUF: mmap; smaller default KV; ModelFileSource still rejects ONNX `external_data`
- No ANN / vector DB; no ONNX QDQ/int8; no LFM2-from-ONNX
- **Java Senior (2026-08-27):** narrative `//` in `Transformer` / `LLM`; some interface params missing `final`; `Example.ModelChoice` holds `Optional<Path>`. Keep array/`for` on hot numeric paths (tensor, sampler, mel, VITS, KV packing).

## 5. Known Issues & Limitations
- CPU-only by default; optional TornadoVM for large dense GEMV only. Weights not in git; LFM2 needs large heap. Security: `security_audit.txt` — parsers/corpus capped; RAG mixes corpus into prompts by design.
- Closing `LlmModel` while an `LLM` still holds the graph leaves dense weights reachable until that LLM closes.
- BERT HF safetensors still rejected. xlm-roberta-base fill-mask mean-pool is anisotropic; `Example` Classify is centered prototypes. Use E5/GTE for retrieval.
- Gemma 4 vision/audio, GGUF Gemma 4, MoE out of scope. Whisper: no MP3/VAD/beam/timestamps. Piper: no streaming/SSML/multi-speaker picker; packaged `ru_dict` omits some lemmas.
- Tests skip via `OptionalModelAssumptions` / `SampleModelAssumptions` when local weights or `./rag` are absent. Packed gte-small Q2_K is slow if left packed.
- Tiny-LLM-ONNX is a toy. Tiny greedy Qwen3+RAG can still invent a famous book despite `RagPrompts.GROUNDING`.

## 6. Open Questions & Pending Decisions
- Piper vs full espeak: compiled rules VM stays out of the Apache JAR (no GPL sources, no JNI).
- Fold Sampler deeper into Transformer? BM25F? HF safetensors LFM2? Broader ONNX remaps for exotic exports?
- Fara / Qwen3.5 (`qwen3_5`) stay unsupported (fail fast). Gemma 4 multimodal / MoE stay out of scope.
- TornadoVM: no Maven version bump available. Further GPU work would be **usage** (cuBLAS GEMV on CUDA SDK, keep activations on device) not a newer jar; OpenCL-only path cannot take Hybrid.

## 8. User Advice and Recommendations
- Pure Java only; no JNI. Hot-path arrays/`for`, not Streams (tensor, attention, sampler, STFT/mel, VITS, KV). TornadoVM is optional and not transitive.
- README stays on the last shipped version — never write SNAPSHOT into badge/coords/JAR names. After a release, `description.md` matches that version. Whisper/Piper/fastText README snippets stay short (API only); full programs live in the sample classes.
- Document Maven as `mvn`; this machine uses `mvn22`.
- New public API after 1.4.0 gets `@since 1.4.1`; do not retag older members. Do not vendor GPL Piper/espeak sources.
- `LLM.builder` for every kind; `.deterministic()` for greedy (not `temperature(0)`). Server: `.dedicatedMatmulPool()`, `.matmulExecutor(appPool)`, or `.disableMultiCpu()`. One `LLM` per in-flight generate; share `LlmModel`. `ResourceLimits.setCurrent` is JVM-global.
- Mix RAG origins on one `RagFactory.builder()`. Do not put hybrid indexing back on `AdvisorRagHelloWorld` / `RagTunerHelloWorld` unless asked.
- Think tags / chat specials: `open(path).thinkTags(…).chatSpecials(…)`; omitted keys fill `DEFAULT`. Streaming `TEXT_RAW` keeps specials; `streamTo` ignores it.
- Piper: `optionalData(ESPEAK_DATA, dir)` when data is not next to the voice; omit or leave missing — TTS still runs.
- Tiny-LLM-ONNX: `onnx/model.onnx` or `model_fp16.onnx`; skip community `*_q4*` / `*_int8*`.
