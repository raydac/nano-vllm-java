## 2. Architecture & Technical Discoveries
- Multi-module: library JAR no longer contains `samples`; demos in `nano-vllm-java-samples` (classpath / `exec:java`, not a JPMS module). Surefire sets `nanollvm.models.dir` / `nanollvm.rag.dir` to `${maven.multiModuleProjectDirectory}/…`; samples `exec:java` uses that directory as `workingDirectory`
- Share one `LlmModel` / `PreparedRag` across many `LLM`s; one LLM not concurrent-safe for generate (`cancel()` is cross-thread)
- Lifecycle: `LLM.close()` frees scheduler + KV/conv arenas + matmul mark (drops network ref); `LlmModel.close()` releases packed payloads / clears weight+network/encoder refs — close engines before model
- `.disableMultiCpu()` / `cpuThreads(1)` → `MatmulRuntime.sequential()` (pool=null, calling thread only); builder thread count wins over `-Dnanollvm.cpu.threads`
- Engine obtains `CausalLM` via `LlmModelAccess.resolveNetwork` (no public `network()`); embedding models hold `EmbeddingEncoder` instead
- BERT GGUF: token+pos+type emb → LayerNorm → post-LN blocks (bidirectional attn + GELU FFN) → mean pool → L2; tokenizer WordPiece with ▁ metaspace pieces
- ONNX: `OnnxProtoReader` reads initializers only; `OnnxWeightNames` maps chat HF names and BERT HF→GGUF schema keys; external_data for `make(Path)` only (not ModelFileSource yet)
- transformers.js / onnx-community: raw payload may be protobuf field **9** (legacy) or **13**; MatMul B is `[in,out]` → transpose to Linear `[out,in]`; anonymous `onnx::MatMul_*` remapped via MatMul node path; `OnnxDataTypes` catalogs TensorProto types — load FLOAT/FP16/BF16/DOUBLE, skip int/bool/string/complex (+ scalars), fail loudly on float8/nibble/unknown
- SmolLM2-135M-Instruct-ONNX = Llama ChatML chat demo; `inviteThinking` is vocab-gated (`<think>`+`</think>`); library `ChatPrompts.systemFor` is always empty — Example uses `SampleChatPrompts` / `SampleAdvisorPrompts` (turn-based demos set sampling/recovery/isolate + advisor note filter)
- base SmolLM2-135M-ONNX / Tiny-LLM-ONNX = completion-only
- GGUF packed by default; late unpack does not release bytes still bound by other engines
- GGUF dequant covers current llama.cpp **weight** `ggml_type`s (K/IQ/TQ/MX/NV/legacy `Q*_0`); file tags `K_M`/`K_S` are mixes. GGUF chat graphs: `qwen3` (unfused `blk.N.*`, `head_dim` from `attention.key_length`) and `lfm2`; embeddings `bert`. Gemma/Llama GGUF still rejected.
- `TEXT_DEBUG`: off unless `ChatSession.emitDebugPrompts(true)` (Example `--debug`); RAG corpus/advisor notes are trusted prompt input by design
- Dense RAG: index-time `LlmModel.embed` of all chunks; query cosine (dot); hybrid = BM25 + dense RRF; off-topic = both indexes agree
- Lexical off-topic uses salient query terms only (skips conversational glue); file-name stems split on `/` and `\`
- Gemma 4 text (QAT mobile): flatten nested `text_config`; skip `vision_tower`/`audio_tower`; packed int2/4/8 + SRQ (`GemmaQat`); PLE after MLP; KV share from last same-type non-shared layer; RMS `onePlusWeight=false`; attn scale 1.0; chat `<|turn>`/`<turn|>`. Weightless `RMSNorm` residual uses `Ops.addRmsNorm(x, residual, eps)` (identity scale; `weight == null` is valid).
- Safetensors shards **> 2 GiB** (Gemma 4 QAT `model.safetensors` is ~2.29 GiB) use `FileChannel` positioned reads; files ≤ 2 GiB still mmap
- Weight/tensor/PDF records hold `byte[]`/`float[]`/`int[]` on purpose (no List boxing); Error Prone `ArrayRecordComponent` is suppressed at those records. Packed QAT/GGUF release is `packed.length == 0`, not identity with a sentinel array. SpotBugs `EI_EXPOSE_REP*` on those types (and `Tensor.data()`, `Context` tables, `Sequence.blockTable()`) is by design — copies would double RAM or break KV mutation.
- Tensor/math perf (2026-08-15): dense decode uses panel GEMV (`FloatKernels.gemv`, x loaded once per K-vector across 8 outputs); Vector `dot`/`sumSquares` 4-acc unroll; `Ops` add/mul/scale/SiLU/GELU/RMSNorm/`tanhSoftcap` go through SIMD kernels; Attention reuses tile scratch, SIMD axpy, and reads paged KV in place (no per-step dense K/V copy). Fused packed dequant-dot still open.


## 3. Technical Debt & Refactoring
- Attention O(n²); no float16 / TP / CUDA; GGUF packed by default; most HF safetensors still FP32 (Gemma 4 QAT stays packed)
- Optional GGUF perf: mmap weights; FP16 / smaller default KV; fused packed GEMM (dequant+dot without float row scratch)
- GGUF metaspace pretok (prepend ▁) may need per-export tuning for exotic packs
- Dense weight `float[]` still GC-only after model close (no eager zeroing of Tensor buffers)
- Dense RAG query embeds synchronize per `DenseRagIndex`; no ANN / vector DB yet
- ONNX: no QDQ/int8; no LFM2-from-ONNX; ModelFileSource rejects external_data sidecars; transformers.js name drift may need more remaps

## 5. Known Issues & Limitations
- Security: see `security_audit.txt` — defaults cap parsers/corpus; RAG mixes corpus into prompts by design
- CPU-only; weights not in git; LFM2 needs large heap for KV/scratch
- Demo `rag/` is English Grimm/LRRH only
- Advisors add latency (one batched generate); matmul pool is process-shared or caller-provided
- Closing `LlmModel` while an `LLM` still holds the graph leaves dense weights reachable until that LLM closes
- BERT embedding GGUFs and ONNX BERT folders; HF safetensors BERT directory load still limited
- Gemma 4 **text** (QAT mobile) loads; vision/audio towers in the same checkpoint are skipped. Gemma 4 GGUF / MoE (`enable_moe_block`) / other Gemma 4 variants are still unsupported. Gemma 3 remains `gemma3` / `gemma3_text`.
- Model/RAG-dependent unit tests skip via test-only `OptionalModelAssumptions` /
  samples `SampleModelAssumptions` (stderr WARNING + JUnit abort) when local weights or `./rag`
  are absent — not shipped with the library JAR
- Tiny-LLM-ONNX (~10M) is a toy checkpoint — expect incoherent text; context is only 1024 tokens
- Lexical `isOutsideCorpus` ignores conversational glue words; still BM25/heuristic (no LLM judge)

## 8. User Advice and Recommendations
- Document Maven as `mvn` (portable); agent on this machine may use `mvn22`
- Prefer `ChatSession` for dialog; raw `generate` for completions
- Custom think/scratchpad markers: `LlmModelFactory.open(path).thinkTags(ThinkTags.of(open, close)).make()`;
  `ChatReply.parse(raw, llm)` uses the model pair; `ChatReply.parse(raw)` still defaults to `<think>`/`</think>`
- Chat markup searched in answers: `open(path).chatSpecials(ChatSpecials.of(…)).make()`; omitted options
  always include `ThinkTags.DEFAULT` and `ChatSpecials.DEFAULT` on `model.options()`
- Raw streaming decode (think tags and chat specials kept): `LlmTextKind.TEXT_RAW` on a `ChatSession` listener;
  `TEXT_THINKING` / `TEXT_ASSISTANT` stay parsed. CLI `streamTo` ignores `TEXT_RAW`.
- Prefer `LlmModelFactory.open` / `make` → `LLM.builder(LlmModel)`; optional `.sampling(params)` on the engine;
  close LLM then model
- Embedding GGUFs/ONNX use the same factory; call `embed`, not `LLM.builder`
- For Tiny-LLM-ONNX use `onnx/model.onnx` (fp32) or `model_fp16.onnx`; skip quantized community files
- Tiny-LLM-ONNX download: `.sh` (Linux/macOS), `.ps1` / `.cmd` (Windows)
- Gemma 4 E2B QAT mobile download: `./models/download-gemma4-e2b-qat-mobile.sh` (or `.ps1` / `.cmd`) → `models/Gemma4-E2B-IT-QAT-Mobile/`
