## 1. Implementation Progress
- TornadoVM decoder layers share one task graph: Llama, Qwen3, Qwen3.5 full attention, Gemma 3, Gemma 4, and LFM2 attention. DeltaNet recurrence and LFM2 short conv stay on the CPU; their MLP is in that graph. Packed and Gemma 4 QAT weights are expanded once. GEMV whose weight span exceeds 32 MiB streams one reusable device tile, so the vocabulary projection is not allocated beside those layers.
- A yes/no prompt ends on `Yes or No:` / `No or Yes:` after `Message:`. The old line `Answer Yes or No.` made Gemma3-270M continue with Yes for every refund state. `JevHelloWorld` asks whether the message asks for a refund, then repeats two states once the prior is on.
- `README.md` is the user guide (what it is, samples, limits). The design tour stays in `description.md`.
- Sample `RussianCheckersHelloWorld`: terminal Russian draughts. User picks one colour; Qwen Jeff plays the other. User's pieces are drawn at the bottom (Black rotates the board 180°). Rank numbers and file letters are on both edges. A single legal move is shown in the prompt; Enter plays it. RAW choice among legal moves. Coordinate entry `a3 b4` / `A 3 B 4`. Jeff usage is documented on `playWithJeff`, `positionText`, `choose`, `narrow`, and `ask`.
- Qwen3.5 text chat (`qwen3_5`): Gated DeltaNet + gated full attention, leading partial RoPE, vision tensors skipped. Jeff-Qwen3.5-0.8B download script. `toJev()` uses the causal logits; no separate Jeff API.
- Compacted causal-graph construction and the generate tick without changing the public API.
- Shared packed-or-dense layer loading in `WeightLayers` (Qwen3, LFM2, BERT, Llama RoPE theta).
- Gemma 3 residual add and embed scale now go through `Ops` (vector kernels) instead of scalar loops.
- Head RMSNorm no longer flattens to rank-2; `RMSNorm.forward` already norms the last axis.
- `WeightBag.asDense` and `asDenseReleasingPacked` share one materialize path.
- Engine step binds KV/conv once via `bindStep`. Prefill slot mapping is its own method.
- `EspeakNgCompiledDict.latinMap()` is gone. `LATIN_MAP` is a `byte[]` of the same 288 entries (values 0–57).
- IQ4NL codebook lives once as `GgufIqTables.kvalues_iq4nl` (signed bytes). `GgufDequant` and `GgufIqDequant` no longer each keep an `int[]` copy.

## 2. Architecture & Technical Discoveries
- Activation buffers: `ActivationWorkspace` is bound for a transformer step. Each causal forward keeps the tensors the next layer still needs and parks the rest (length ≥ 256) for reuse. `prefillLogits` detaches the returned logits so the freelist cannot overwrite them. `Sequence.pagedSlots` grows one slot index per sequence; `Context` publishes it once per step. `Sampler` selects top-k with an `int` heap. Nucleus sampling pops that same order until the cumulative mass reaches top-p, instead of mergesorting the vocabulary.
- Zero-length `byte[]`, `int[]`, `float[]`, and `float[][]` are the shared `EmptyArrays` constants. `Tensor.zeros` with `numel == 0` returns that `float[]`. Tornado's no-bias sentinel is its own one-element array: TornadoVM 8 requires every kernel array to be transferred, and a zero-length buffer is not a device argument.
- Speed review (inference hot path): multi-token `gemvRows` walks an 8-row weight panel across every token before the next panel (scalar and Vector). Decode (`rows == 1`) stays one GEMV. A JevHelloWorld hotspot export (`jevhotspot.csv`) was 86% CPU in `ScalarFloatKernels.gemvPanel8` — that JVM had no Vector API (`--add-modules jdk.incubator.vector`); IntelliJ does not load `.mvn/jvm.config`. On this i7-8550U (AVX2, 8 lanes), vector panel-across-tokens was ~12× the profiled scalar per-token GEMV on a 96×640×4096 prefill. TornadoVM mode runs GEMV (including one token), attention (including one query), and elementwise kernels on the device. Decode matmul is one launch (`prefersSingleShotGemv`). One-token GEMV uses the device kernel; CLBlast stays multi-token only (SGEMV returned NaN on POCL). RMSNorm is one device task for every row, not one launch per head. Attention history stays on the device and a later step copies only the new token. Gated DeltaNet stays on the CPU. UHD 620 does not beat AVX2 on single-token F32 GEMV, so a Tornado chat can be slower than Vector and that measurement is the device.

- Qwen3.5 text is architecture `qwen3_5`, not an alias of `qwen3`. Full-attention layers use leading partial RoPE (text-only; MRoPE collapses when positions match). Linear layers keep conv + recurrent state in `DeltaNetStateArena`, cleared with the existing conv-state hook. HF names `model.language_model.*` and root `language_model.*` (Jeff checkpoint) both canonicalize to `model.*`. The same peel covers `text_model`, `base_model.model`, and a repeated `model.model`. Packed Q/K/V and gate/up merge only when the schema does not already name that tensor, and only as a whole path segment. A second copy or a matrix that is not config `[out, in]` (or that layout swapped) fails the load. `q_proj` stays unfused (query | gate). Gemma 4 QAT uses the same name peel and rejects a duplicate tensor.
- `RMSNorm.forward` walks `numel / lastDim` rows, so a `[tokens, heads, headDim]` tensor matches the old reshape-to-2d-then-back path.
- `HfConfig` compact constructor freezes a null `ropeScaling` to an empty map, so `WeightLayers.ropeTheta` can call `containsKey` directly.
- `IntStream.toList()` is already unmodifiable; `List.copyOf` around it was an extra copy.
- Public `LLM.generate` / `generateTokenIds` overloads stay: they are the caller-facing surface.
- TornadoVM Maven coordinate is `8.0.0-jdk22plus` (JDK 22+, including 27). Optional `tornado-clblast` is compile-only. Multi-token dense GEMV uses CLBlast SGEMM when `libclblast` runs. One-token GEMV never reaches CLBlast (SGEMV returned NaN on POCL) and uses the device kernel from TornadoVM's `MatrixVectorRowMajor` example: one workgroup of 128 lanes per output row, coalesced weight reads, 4 accumulators, local reduction. One thread per row was the slow shape (their example measured about 10× slower than the workgroup kernel). A non-finite CLBlast result or a failed launch drops CLBlast for the rest of the process. `-Dnanollvm.tornado.clblast=false` keeps the multi-token kernel. The weight slice is copied once into a Tornado `FloatArray`. Weights and the bias sentinel stay resident (`FIRST_EXECUTION`) for one token count. A change of token count closes those plans first: prefill and decode would otherwise each keep a device copy, and the second copy of Qwen3-0.6B `gate_up` (24 MB) overflows the 4 GB `tornado.device.memory` heap. A GEMV whose weight span exceeds 32 MiB, including the Qwen3-0.6B LM head (~593 MB, the 622329872-byte alloc), is copied through one reusable device tile instead of one buffer. Qwen3 dense layers do not use that per-call GEMV: one task graph per layer runs norm, QKV, RoPE, paged attention, and the MLP, and prefill walks it one token at a time so the weights are not uploaded again. The activation between those tasks stays on the device. Llama, Gemma 3, Gemma 4, Qwen3 (fused or separate projections, including packed weights expanded once), Qwen3.5 full attention, and LFM2 attention use that same layer graph. Gemma 4 QAT is dequantized once and the SRQ scales stay in the graph. A shared-KV Gemma 4 layer re-reads the producer cache from the host each token. Qwen3.5 Gated DeltaNet recurrence and LFM2 short convolution stay on the CPU; their MLP is still one device graph. Chat attention, including a single decode query, is one task graph: an append of the new token, then the score. The resident cache is `FIRST_EXECUTION`; a replaced cache is refreshed with `transferToDevice`. A failed attention launch fails the step. cuDNN packed-QKV attention is CUDA-only and does not match causal grouped-query attention with a sliding window.
- OpenCL devices outside the sandbox: `0:0` Intel UHD Graphics 620 (Tornado default), `0:1` POCL CPU. A sandboxed `tornado --devices` sees only POCL. `etc/tornado.backend` is OpenCL only. The CUDA driver jar can still abort startup when `libcuda` is missing, so the TornadoVM bench child passes `-Dtornado.enabled.backends=OpenCL`. `libclblast.so.1` is on the SDK `lib` path.
- `KernelChatBench` child JVMs must use the context class loader URLs. Under `mvn exec:java`, `java.class.path` is Maven's classpath. The TornadoVM child must be started with the `tornado` command (`tornado.exe` on Windows): the Maven parent never loads the SDK, so a parent device probe skips TornadoVM even when `tornado --devices` lists both OpenCL devices. The extensionless `bin/tornado` in the Windows SDK is a shell script; CreateProcess error 193 is that file. The `windows` Maven profile sets `tornado.launcher` to `tornado.exe`. When `TORNADOVM_HOME` is set, profile `tornadovm-home` points `tornado.executable` at `$TORNADOVM_HOME/bin/<launcher>`. `KernelChatBench` already resolves PATH then `TORNADOVM_HOME/bin`.

## 3. Technical Debt & Refactoring
- GGUF IQ tables, Tornado kernels, and espeak dictionaries are data or numeric kernels. Do not “compact” them into shared abstractions.
- Java causal graphs still repeat decoder-layer shape. Tornado uses one shared layer graph; Gated DeltaNet and LFM2 short conv remain CPU steps in front of that graph's MLP.
- `LLM` still has many one-line generate overloads. They exist so callers do not pass unused flags.

## 4. Current Work In Progress
- Speed work stays algorithmic. Nucleus sampling keeps a heap prefix instead of sorting the vocabulary. Vector GEMV stays one 8-row panel on `SPECIES_PREFERRED`. Splitting that panel onto `SPECIES_256` / a 2-row kernel was a JDK 27 inliner trick: the 2-row form measured slower (about 8 tok/s vs 11 tok/s on the same 4×16×8 Qwen3-0.6B smoke) and still spent most samples in the lane fallback.
- KernelChatBench Qwen3-0.6B, 46 prompt + 256 completion, after the per-op device path: scalar 4.05 tok/s, Vector 6.89 (1.70×), TornadoVM 0.72 (0.18×). That Tornado run was one launch per GEMV, norm, and attention, with the activation copied back each time. Dense decoder layers now share one Tornado task graph (Llama, Qwen3, Qwen3.5 attention, Gemma 3, Gemma 4, LFM2 attention). DeltaNet recurrence and LFM2 short conv stay on the CPU. The next tornado bench died in the LM head allocating 622329872 bytes (Qwen3-0.6B vocab, 151936×1024) after those graphs were resident. GEMV above 32 MiB now streams one device tile. Remeasure before quoting tok/s.
- `Bench` Maven profile `bench` forks the timed generate under async-profiler 4.6. `package` and `exec:exec@bench` must be the same invocation, or the classpath is an older installed snapshot. Reports: `nano-vllm-java-samples/target/bench-profile/`.
- Activation reuse, paged slot cache, and primitive top-k select are in. `CoreUnitTest` covers zeroed buffer reuse, detached logits, and append-only slot growth. Prefill GEMV reuses an 8-row weight panel across tokens (`batchedGemvMatchesPerTokenGemv`). Tornado one-token matmul and one-query attention run on the device (`oneTokenMatmulAndOneQueryAttentionRunOnTheDevice`). Re-profile `JevHelloWorld` with `--add-modules jdk.incubator.vector` so a Vector run's hotspot is `VectorFloatKernels`, not scalar.

- `KernelChatBench` on Windows resolves `tornado.exe` from `PATH` or `TORNADOVM_HOME/bin`, and the `windows` Maven profile sets `tornado.executable` to `tornado.exe`. Worker `--classpath` / `--params` are shell-quoted because TornadoVM pastes them into `os.system`/`cmd.exe`: unquoted `;` truncates the classpath (NoClassDefFoundError for library classes), and Unix single quotes break `Path.of`. The tornado child also drops `CLASSPATH` so the launcher cannot append it with a Unix `:`. Default model is `requireKernelChatBench()` (Qwen3-0.6B → Gemma3 → Jeff → Gemma4 → SmolLM2); compact ONNX prints a note that Tornado ratios are launch-bound.
- `JevLevel` javadoc now states RAW vs L0 (rotations, eight-state prior, ordered scores stay one prefill) and includes a two-engine usage example. `require` and `Builder.jevLevel` point at it.
- Russian checkers records (`Sq`, `Move`, `Played`, `Choice`, `Step`, `Hop`) have javadoc for the short components: file/rank axes, path vs captured vs crowned `result`, forced single-move turns, and a hop's land/victim.
- Board a–h axis is `Sq.column` (0 = a). `Step` uses `columnDelta` and `rankDelta`. Screen position in the rotated drawing is `across`, not `column`.
- Jeff's checkers prompt does not ask for a written plan. Jev reads the next letter and the chat template closes an empty think block. `positionText` lists pieces; `choiceLabel` notes captures, promotion, a win, or `landing taken at once`. The question states that preference order.
- Russian checkers sample is in (`RussianCheckersHelloWorld`). Rules covered by `RussianCheckersHelloWorldTest` (no model load). A live game still needs `models/Jeff-Qwen3.5-0.8B`.
- Qwen3.5 text load is in: hybrid Gated DeltaNet + gated attention, leading partial RoPE, delta-state arena, `models/download-jeff-qwen3.5-0.8b.sh`. Vision tower and the Jeff readout head are not loaded. `toJev()` uses the causal logits. Jeff safetensors use a `language_model.*` prefix; that now maps onto `model.*`. Real Jeff-Qwen3.5-0.8B loaded and produced one token.
- Model loader rejects duplicate and wrong-shaped weights. Wrapper prefixes (`language_model`, `text_model`, `base_model`, `model.model`) and a swapped `[in, out]` matrix still bind to the schema name. Covered by `ModelLoaderTest`.

## 5. Known Issues & Limitations
- Qwen3.5 support is text-only safetensors. Vision inputs, LoRA adapters, Qwen3-Next, and Qwen3.5 MoE stay rejected. GGUF is not a load path for `qwen3_5`.
- Tornado kernel tests skip when no Tornado device is on the module path. Maven Surefire does not launch the `tornado` CLI, so those tests skip there.

## 8. User Advice and Recommendations
- README commands use `mvn`. Do not put local launcher names (`mvn22`), machine paths, or bench-profile property recipes in `README.md`.
- Keep public generate overloads. Compact internals, not the caller API.
- Optimize algorithms in Java. Do not shape kernels around the current JVM's inliner or Vector API intrinsification; that changes between JDKs.
